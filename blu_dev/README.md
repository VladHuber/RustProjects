# blu_dev — Bluetooth Battery Monitor (GUI)

Приложение с графическим интерфейсом на `eframe`/`egui`: сканирует BLE-устройства, читает уровень заряда
и показывает список с прогресс-барами. Умеет сворачиваться в системный трей и прописывать себя в автозапуск.

## Что делает

- асинхронно сканирует окружение через `btleplug` (`Central` / `Peripheral`);
- читает характеристику **Battery Level (0x2A19)** у найденных устройств (`try_read_battery`);
- выводит список устройств: имя, адрес, заряд и `ProgressBar`;
- иконка в трее (`tray-icon` + `image`), сворачивание окна вместо закрытия;
- включает автозапуск через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (`winreg`);
- интерфейс обновляется по таймеру (~15 с), скан длится ~10 с.

## Как запустить

```bash
cd blu_dev
cargo run --release
```

Windows + Bluetooth-адаптер. Для чтения заряда устройство должно поддерживать GATT-характеристику 0x2A19
(наушники и колонки обычно поддерживают, классические устройства — нет).

## Техника и зависимости

`btleplug` 0.11 (BLE), `eframe`/`egui` 0.24 (GUI), `tokio` 1.35 (full) — асинхронный скан,
`uuid` (фильтр сервисов), `winreg` (автозапуск), `tray-icon` + `image` (трей), `anyhow` для ошибок
в инициализации, сканировании и работе с реестром.

## Честные ограничения

- вся логика — в одном файле `src/main.rs` (~550 строк, 12 функций), без модулей;
- 18 вызовов `unwrap()` (мьютексы, `TrayIconBuilder::build()`, создание tokio-рантайма) — при сбое
  приложение упадёт вместо понятной ошибки;
- мёртвый код: `command_receiver` и `create_battery_icon_with_level` не используются,
  `futures` и `winapi` объявлены в `Cargo.toml`, но в коде не нужны; параметры `create_tray_icon`
  игнорируются;
- создаётся два tokio-рантайма (второй — на каждый скан), это лишние потоки;
- `connected` выставляется и тут же сбрасывается, то есть статус подключения по факту не отслеживается;
- тестов нет.
