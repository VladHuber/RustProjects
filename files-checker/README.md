# files-checker — демон-наблюдатель за каталогом

Фоновый процесс, который следит за изменениями в каталоге, ведёт лог и при необходимости присылает
уведомления в Telegram.

## Что делает

- рекурсивно слушает события файловой системы (`notify`): создание, изменение, удаление;
- **дебаунс 3 секунды** — повторные события по одному и тому же пути не порождают поток сообщений;
- игнорирует файлы по glob-маске (`--ignore "*.tmp"`) и собственный лог `app.log`;
- пишет лог в stdout и в файл `app.log` (`fern` + `log`);
- опционально отправляет уведомление в Telegram (`--telegram <chat_id>`, токен бота — из `config_app.json`).

## Как запустить

```bash
cd files-checker
copy config_app.example.json config_app.json    # вписать токен бота и chat_id
cargo run -- --dir "D:\Downloads" --ignore "*.tmp" --telegram 123456789
```

`--telegram` **необязателен**: если аргумент не передан, конфиг отсутствует или токен пустой —
программа пишет предупреждение и продолжает работать без уведомлений (раньше в этом случае была паника).

## Чем интересен

- CLI на `clap` с обязательными `--dir` / `--ignore` и опциональным `--telegram`;
- вся логика вынесена в библиотеку `src/lib.rs` — `is_ignored`, `should_process_event`, `event_message`,
  `load_telegram_token`, `TelegramNotifier` — а `main.rs` остался тонкой обвязкой; это позволяет
  тестировать поведение без сети и без файловой системы;
- **ни одного `unwrap()` / `expect()` / `panic!`** в `src/`: отсутствие аргумента, битый конфиг, ошибка
  сети и не-UTF-8 путь дают запись в лог, а не падение;
- 8 тестов проходят офлайн: glob-игнор, игнор `app.log`, дебаунс (первое событие, повторы, истечение
  окна), тексты уведомлений, отсутствующий конфиг.

Зависимости: `clap` 4.5, `notify` 8.0, `fern` 0.7, `log` 0.4, `reqwest` 0.12 (blocking, json),
`serde` + `serde_json`, `glob` 0.3, `chrono` 0.4, `urlencoding` 2.1.

## Безопасность

- `config_app.json` содержит токен бота и **не коммитится** (в `.gitignore`); в репозитории лежит
  `config_app.example.json` с заглушками;
- если токен когда-либо попадал в чужой доступ (в лог, в коммит, в архив) — его нужно **отозвать
  у @BotFather** и выпустить новый.

## Честные ограничения

- блокирующий HTTP и `thread::sleep` вызываются внутри колбэка `notify`: при медленной сети обработка
  событий задерживается;
- конфиг и лог ищутся по относительным путям (`./config_app.json`, `app.log`) — запускать удобнее
  из корня проекта;
- дебаунс хранится в памяти процесса (`HashMap`), при перезапуске состояние сбрасывается;
- нет graceful shutdown и ротации логов.
