# log_analyzer — анализ nginx access.log

Консольный анализатор логов веб-сервера: разбирает формат nginx combined и печатает отчёт по трафику,
ошибкам и аномалиям.

## Что делает

- считает общее число запросов, период и суммарный размер ответов;
- **TOP кодов ответа** и отдельно TOP ошибок (4xx/5xx);
- топ-5 методов, путей и IP-адресов;
- рисует ASCII-гистограмму запросов по часам;
- ищет аномалии: часы, где количество 5xx превышает среднее в `ANOMALY_THRESHOLD` (1.5) раза.

## Как запустить

```bash
cd log_analyzer
cargo run                        # по умолчанию ./test_data/access.log
cargo run -- C:\logs\access.log  # или явный путь
```

Путь к логу — необязательный аргумент. Если файл не читается, выводится понятное сообщение в stderr
и код возврата 1.

## Чем интересен

- строгий регексп `NGINX_COMBINED_PATTERN`: собран через `concat!`, без `(?x)`-режима, с анкором `^…$`
  и именованными группами — `ip`, дата, время, таймзона, `method`, `path`, `protocol`, `status`, `size`,
  `referer`, `agent`; блок `referer`+`agent` необязателен, поэтому принимается и common log format;
- время валидируется через `NaiveTime::parse_from_str` — строки с несуществующим временем отбрасываются;
- пустой лог и отсутствие 5xx обрабатываются аккуратно: никаких делений на ноль и `NaN`;
- аномалии сортируются по часу, поэтому вывод детерминирован (раньше зависел от порядка `HashMap`);
- **6 тестов**, в том числе проверка, что все 57 строк тестового лога действительно разбираются,
  и что пустой лог не даёт `NaN`.

Зависимости: `regex` 1.11, `chrono` 0.4 (edition 2024).

## Пример вывода

```
=== Анализ лога: ./test_data/access.log ===
Всего запросов: 57
Период: 15:30:22 .. 19:32:22
Суммарный размер ответов: 70338 байт

TOP кодов ответа:
  500: 54
  200: 2
  404: 1

Топ-5 методов:
  GET: 57

Топ-5 IP-адресов:
  192.168.1.1: 57

График запросов в час:
19:00 |    53 | ██████████

Поиск аномалий (5xx в час > среднего в 1.5 раза):
  Аномалия: в 19:00 было 53 5xx-ошибок (среднее по часам с ошибками: 27.0)
```

## Честные ограничения

- путь извлекается как `\S+`, то есть пробелы внутри пути не поддерживаются (nginx их экранирует);
- таймзона только фиксируется — время между зонами не нормализуется; дата разбирается, но в отчёте
  не используется;
- среднее для аномалий считается по часам, где были 5xx (это прямо написано в отчёте), поэтому
  на маленькой выборке метрика грубая;
- лог читается в память целиком.
