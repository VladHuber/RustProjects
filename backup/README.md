# backup — CLI-бэкапер с трейт-стратегией

Утилита командной строки: считает контрольные суммы каталога, складывает его в архив и умеет повторять
это по расписанию. Единственный проект в портфолио с абстракцией формата архива через трейт.

## Что делает

- `--src <каталог>` — что бэкапить, `--dest <каталог>` — куда складывать, `--schedule daily|weekly` — период повторения;
- рекурсивно обходит источник, считает **SHA-256** каждого файла и пишет `checksums.sha256`
  (относительные пути); сам файл сумм из обхода исключён — он не хеширует себя;
- создаёт архив: **zip** на Windows, **tar.gz** на Linux (выбор по целевой ОС);
- имя архива уникально (`backup-<метка времени>.zip`), внутри сохраняется структура каталогов
  относительно `--src`;
- **первый бэкап делается сразу** при запуске, дальше — по расписанию (`clokwerk`);
- защита от ошибок: архивирование внутрь `--src` отвергается, симлинки не разворачиваются
  (`follow_links(false)`), ошибки возвращаются через `Result`, а не через панику.

## Как запустить

```bash
cd backup
cargo run -- --src C:\path\to\data --dest C:\path\to\backups --schedule daily
```

## Чем интересен

- трейт **`ArchiveStrategy`** и две реализации — `ZipStrategy` и `TarGzStrategy`, выбор через
  `get_archive_strategy` / `ArchiveFormat`: чтобы добавить формат, достаточно новой реализации трейта;
- `pub fn collect_files(&Path) -> io::Result<Vec<PathBuf>>` на `walkdir` — рекурсивный сбор файлов
  с сортировкой и исключением файла сумм; используется и стратегиями, и подсчётом контрольных сумм;
- корректная финализация tar.gz: `tar.finish()` → `into_inner()` → `encoder.finish()` → `flush()`
  (без этого архив остаётся недописанным);
- 6 интеграционных тестов на изолированных временных каталогах: проверяют рекурсивный обход,
  создание и чтение обоих архивов, структуру внутри архива и самоисключение `checksums.sha256`.

Зависимости: `clap` 4.5 (CLI), `clokwerk` 0.4 (расписание), `sha2` 0.10 (SHA-256), `zip` 4.0,
`flate2` 1.1 + `tar` 0.4 (tar.gz), `walkdir` 2.5.

## Структура

```
backup/
├── src/
│   ├── lib.rs                     стратегии архивации, сбор файлов, контрольные суммы
│   └── main.rs                    CLI (clap) и планировщик (clokwerk)
├── tests/
│   ├── integration_test.rs        6 тестов на временных каталогах
│   └── common/mod.rs              хелперы для temp-каталогов и чтения архивов
└── examples/                      пример входных данных и результат checksums
```

## Честные ограничения

- Формат выбирается по целевой ОС, поэтому на Windows бинарник всегда пишет zip; tar.gz-ветка покрыта
  интеграционным тестом (включая проверку gzip-трейлера), но нативно на Windows не запускается.
- Планировщик работает бесконечным циклом без graceful shutdown — выход по `Ctrl+C`.
- Сигнатура трейта возвращает `Result<(), String>` (сохранена ради `Box<dyn ArchiveStrategy>`),
  конвертация в `io::Error` / `Box<dyn Error>` происходит в `main.rs` и тестах.
